# Результаты статического технического аудита

## Область аудита

Проверен исходный код репозитория linkPrewievService, ветка master, commit `52fb7103d21f7d6bbc84a9da5f41c686b4ec534d`.

Аудит статический: анализировались файлы и связи между ними. Сетевые сценарии, эксплуатация в production и фактическая доступность внешних API не проверялись. Исправления в код не вносились.

## Сводка

### Высокий приоритет

#### A-01. Отсутствует защита от SSRF на входе API

**Файлы:** `routes/api.js`, `middleware/singleFlightCache.js`, `previewGeneratorEngine/sitesCrawler.js`, `previewGeneratorEngine/getImage.js`.

API принимает пользовательский URL и передаёт его в сетевые запросы Got. В crawler разрешены редиректы до 10 переходов. В видимом коде не обнаружены проверки схемы, IP-адресов назначения, localhost/private/reserved диапазонов и повторная проверка адреса после редиректа. Проверка CORS не является защитой для server-to-server запросов.

**Риск:** при доступности endpoint извне его можно попытаться использовать для обращения к внутренним сетевым ресурсам от имени сервера.

**Рекомендация:** валидировать URL и разрешённые схемы; блокировать локальные, private, link-local и reserved IP; проверять DNS-результаты и каждый redirect target; учитывать DNS rebinding; ограничить исходящий сетевой доступ на уровне инфраструктуры.

#### A-02. Секреты содержатся в отслеживаемом env-файле

**Файл:** `debugWhitelist.env`.

В файле обнаружены непустые значения YOUTUBE_API_KEY и KINOPOISK_API_KEY. Файл присутствует в Git-дереве и не исключён .gitignore.

**Риск:** ключи доступны всем, кто имеет доступ к репозиторию и его истории. Документация не раскрывает их значения.

**Рекомендация:** отозвать/перевыпустить ключи, удалить секреты из рабочей конфигурации Git, использовать секреты окружения хостинга или локальные неотслеживаемые env-файлы. При необходимости очистить историю Git.

#### A-03. Возможная XSS в тестовой странице

**Файл:** `views/index.html`.

Данные ответа API вставляются через `result.innerHTML`. Значения title, description, url и image формируются из внешнего содержимого и вставляются в HTML без экранирования.

**Риск:** внешняя страница может контролировать метаданные, которые встраиваются в тестовую страницу как HTML/атрибуты.

**Рекомендация:** создавать DOM-элементы и задавать текст через textContent, ссылки и изображения — через свойства DOM; при необходимости применять строгую политику URL и CSP. Не использовать innerHTML для недоверенных данных.

### Средний приоритет

#### A-04. YouTube блокируется до вызова специального обработчика

**Файлы:** `blockedDomains.json`, `previewGeneratorEngine/previewGenerator.js`.

youtube.com присутствует в blockedDomains. Проверка `rules.skipParsing` выполняется до `isYoutubeLink()`. Следовательно, обычный YouTube URL пропускается раньше специализированной ветки.

**Рекомендация:** определить ожидаемую политику YouTube и согласовать её с порядком специальных обработчиков и блок-листом.

#### A-05. Поддержка youtu.be и Shorts не соответствует извлечению video ID

**Файлы:** `utils/youtubePreviewHandler.js`, `utils/fetchYoutubeMetadata.js`.

Проверка isYoutubeLink заявляет поддержку youtu.be и Shorts, но video ID извлекается только регулярным выражением для query-параметра v. Для URL без v ID не будет найден.

**Рекомендация:** централизованно разбирать YouTube URL через URL API и поддержать каждый заявленный формат.

#### A-06. Кеш не является LRU по последнему использованию

**Файл:** `middleware/singleFlightCache.js`.

При чтении cache hit ключ не удаляется и не добавляется повторно в конец Map. При превышении лимита удаляется ключ, который дольше всех находится в Map, а не запись с самым давним обращением.

**Рекомендация:** либо переименовать/описать механизм как FIFO/insertion-order cache, либо обновлять порядок ключа при чтении.

#### A-07. В кеш попадают результаты нестандартных типов

**Файлы:** `middleware/singleFlightCache.js`, `previewGeneratorEngine/previewGenerator.js`.

Middleware сохраняет любое успешно разрешившееся значение. `parseUrl()` может вернуть строку `"test"`, а специализированные handlers — `null`. При cache hit и shared response используется объектный spread, из-за чего ответ для таких значений может отличаться от первоначального.

**Рекомендация:** определить единый контракт результата и кешировать только валидные объекты предпросмотра либо явно обрабатывать null/error состояния.

#### A-08. BLACKLISTMODE не управляет блокировкой

**Файлы:** `previewGeneratorEngine/previewGenerator.js`, `previewGeneratorEngine/parsingRulesManager.js`.

Переменная читается в parseUrl, но не передаётся getParsingRules. blockedDomains проверяется безусловно.

**Рекомендация:** определить смысл режима и реализовать его явно либо удалить неиспользуемую настройку в отдельной задаче.

#### A-09. Необработанный тип error от crawler

**Файлы:** `previewGeneratorEngine/sitesCrawler.js`, `previewGeneratorEngine/previewGenerator.js`.

В verbose-режиме crawler возвращает объект `type: "error"` при ошибке полного fetch. parseUrl проверяет только `type === "file"`, после чего продолжает работу с отсутствующим html.

**Рекомендация:** явно разбирать все варианты результата crawler и возвращать контролируемую ошибку/типизированный результат.

#### A-10. Внешний catch parseUrl возвращает строку

**Файл:** `previewGeneratorEngine/previewGenerator.js`.

При исключении в обычном конвейере возвращается строка `"test"`. Это нарушает ожидаемую структуру предпросмотра и создаёт проблемы для кеширования и клиентских потребителей.

**Рекомендация:** определить единый формат ошибок и не смешивать его с обычным preview object.

#### A-11. onlyPoster несовместим с проверкой title на CyTube-клиенте

**Файлы:** `previewGeneratorEngine/previewGenerator.js`, `public/javascripts/linkPreviewFrontendModule.js`.

При onlyPoster сервер возвращает пустой title. Клиентский модуль отказывается строить карточку, если title отсутствует, даже при наличии image.

**Рекомендация:** согласовать критерий отображения карточки с режимом onlyPoster.

#### A-12. Возможны лишние расходы CPU/памяти в streaming crawler

**Файл:** `previewGeneratorEngine/sitesCrawler.js`.

При каждом событии data выполняются Buffer.concat по всем накопленным chunks и декодирование накопленного буфера. На длинных страницах это может приводить к повторной обработке одних и тех же байтов. Переменная prefixLen вычисляется, но далее не используется; StringDecoder создаётся, но фактически не используется.

**Рекомендация:** профилировать crawler и рассмотреть инкрементальное сканирование/декодирование и ограниченный prefix buffer.

#### A-13. Дублируются системы логирования

**Файлы:** `utils/logger.js`, `utils/debugHandler.js` и модули, импортирующие их.

В проекте параллельно используются централизованный логгер и отдельный консольный debugHandler. Это создаёт разные форматы и правила фильтрации.

**Позиция проекта:** `utils/logger.js` — целевой логгер. Перевод оставшихся вызовов на него — последующая задача, не часть документирования.

**Дополнительное наблюдение:** часть вызовов appLog из `fetchYoutubeMetadata.js` передаёт поле `msg`, в то время как logger.js читает `record.message`. Текст таких сообщений может отсутствовать в основной записи.

**Рекомендация:** при будущей унификации согласовать единый формат вызова, нормализовать поля и покрыть logger тестами.

#### A-14. DEBUG_LEVEL влияет на режим crawler

**Файл:** `previewGeneratorEngine/sitesCrawler.js`.

При значении verbose включается полный fetch вместо потокового. Поэтому изменение уровня логирования меняет не только объём логов, но и сетевую/вычислительную стратегию.

**Рекомендация:** в будущем разделить режим получения HTML и уровень логирования, если такое поведение не является осознанным требованием.

#### A-15. debugHandler не фильтрует уровни так, как описано

**Файл:** `utils/debugHandler.js`.

Если DEBUG_LEVEL задан, shouldLog возвращает true для любого уровня. В результате переменная не задаёт порог фильтрации в этом модуле, а просто включает все его сообщения.

**Рекомендация:** согласовать ожидаемую семантику уровней с целевым logger.js.

### Низкий приоритет и качество сопровождения

#### A-16. Дублирующийся домен

**Файл:** `parsingRules.json`.

Домен mail.ru встречается дважды. Для find используется Array.find, следовательно, применяется первое совпавшее правило.

**Рекомендация:** убрать неоднозначность и документировать приоритет правил.

#### A-17. Отсутствуют package-lock и автоматизированные тесты

В корне нет package-lock.json, в package.json нет test-скрипта, в дереве не обнаружены тестовые файлы.

**Рекомендация:** добавить lock-файл и тесты после определения основных контрактов и сценариев.

#### A-18. Скрипты ссылаются на отсутствующие env-файлы

**Файл:** package.json.

start_verbose и start_debug ожидают verbose.env и debug.env, которых нет в текущем дереве. start_debug_whitelist использует присутствующий debugWhitelist.env, содержащий секреты.

**Рекомендация:** согласовать скрипты с безопасной конфигурацией окружения.

#### A-19. Жёстко задан Render URL в CyTube-модуле

**Файл:** `public/javascripts/linkPreviewFrontendModule.js`.

API_BASE захардкожен как URL старого Render deployment. Это может не соответствовать фактическому месту размещения новой копии.

**Рекомендация:** вынести endpoint в конфигурацию интеграции.

## Не является дефектом само по себе

- Отсутствие README в исходном проекте — документация теперь размещается в docs.
- Отсутствие прежнего устаревшего файла — не считается проблемой без подтверждения, что на него всё ещё есть ссылки.
- Наличие отдельного debugHandler — известное текущее состояние; целевой план — последующая миграция на logger.js.
- Значения classification сами по себе не являются механизмом модерации; это текущая реализация, которую нужно сопоставить с требованиями, а не автоматически исправлять.

## Итоговая оценка

Самый высокий риск связан с тем, что API принимает произвольный пользовательский URL и выполняет сетевые запросы без видимых проверок SSRF, а в репозитории присутствует env-файл с ключами API. Отдельно необходимо устранить XSS в тестовом интерфейсе.

Остальные замечания в основном касаются расхождения контрактов, управления доменными правилами, обработки ошибок и сопровождения. Исправления не выполнялись.
