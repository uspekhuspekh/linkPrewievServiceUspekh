# Обзор проекта

## Назначение

linkPrewievService — Node.js-сервис, который получает URL веб-страницы, извлекает её метаданные и формирует JSON-объект для предпросмотра ссылки. Основные данные предпросмотра: исходный URL, заголовок, описание и изображение.

Для обычных сайтов сервис загружает HTML и анализирует его. Для YouTube и Кинопоиска предусмотрены отдельные обработчики, использующие внешние API.

В репозитории также находятся простая тестовая веб-страница и отдельный клиентский JavaScript-модуль для добавления карточек предпросмотра в чат CyTube.

## Технологии

- Node.js 22.22.2, ES Modules.
- Express 4 — HTTP-сервер и маршрутизация.
- Got — HTTP-запросы к страницам и внешним API.
- Metascraper и его плагины — извлечение метаданных.
- Cheerio — разбор HTML и поиск элементов.
- iconv-lite и chardet — определение и декодирование текстовой кодировки.
- CORS — ограничение браузерных cross-origin запросов по списку origins.
- Собственные модули логирования в `utils/logger.js` и `utils/debugHandler.js`.

Полный список прямых зависимостей находится в корневом `package.json`.

## Основные возможности текущей реализации

1. HTTP API `GET /api/parse?url=...`.
2. Извлечение заголовка, описания и изображения обычной веб-страницы.
3. Потоковая загрузка HTML с возможностью досрочно остановить чтение.
4. Выбор скорости/стратегии загрузки через доменные правила и параметр `fastmode`.
5. Правила доменов в `parsingRules.json`, список блокируемых доменов в `blockedDomains.json`.
6. Контроль выдачи постеров и режим «только постер».
7. Специализированный предпросмотр YouTube через YouTube Data API.
8. Специализированный предпросмотр фильмов и сериалов Кинопоиска через сторонний API.
9. In-memory кеш и single-flight для одинаковых URL.
10. Файловое и консольное логирование.

## Общая схема

HTTP-запрос проходит через Express-маршрут и middleware кеширования. При отсутствии кешированного или уже выполняющегося результата вызывается `parseUrl()`. Она рассчитывает правила домена, проверяет специальные обработчики и, для обычных сайтов, последовательно вызывает crawler, извлечение метаданных и выбор изображения.

Подробности приведены в [архитектуре](architecture.md) и [потоке обработки](request-flow.md).

## Границы и то, чего проект не делает

По текущему коду не обнаружены база данных, постоянное хранилище кеша, очередь фоновых задач, система пользователей или авторизация API. Кеш существует в памяти процесса и очищается при перезапуске.

Классификации доменов `safe`, `moderate`, `warn` и `other` присутствуют в правилах, но отдельная система модерации содержимого на их основе в текущем конвейере не реализована.
