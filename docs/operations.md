# Запуск и обслуживание

## Требования

- Node.js версии 22.22.2 (указана в поле engines файла package.json).
- npm.
- Доступ к сети для загрузки зависимостей и получения страниц.
- Для специализированных интеграций — API-ключи YouTube и Kinopoisk.

## Установка

После клонирования репозитория:

```bash
npm install
```

В репозитории на момент аудита нет package-lock.json. Поэтому npm может разрешить диапазоны версий зависимостей иначе, чем в первоначальной среде разработки. Для повторяемых установок в будущем стоит добавить и поддерживать lock-файл, но это не входит в текущую задачу документирования.

## Обычный запуск

```bash
npm start
```

Команда выполняет `node ./app.js`.

По умолчанию сервер слушает порт 3002. Для другого порта задайте переменную `PORT`.

После запуска локальная тестовая страница доступна по адресу:

```text
http://localhost:3002/
```

API:

```text
http://localhost:3002/api/parse?url=https%3A%2F%2Fexample.com
```

## Переменные окружения и API-ключи

Для работы YouTube нужен `YOUTUBE_API_KEY`, для Kinopoisk — `KINOPOISK_API_KEY`. Остальные настройки описаны в [configuration.md](configuration.md).

Не храните реальные ключи в отслеживаемых Git-файлах. На момент аудита файл `debugWhitelist.env` находился в репозитории и содержал ключи; их необходимо перевыпустить до дальнейшего использования.

## Режимы запуска из package.json

| Команда | Env-файл | Назначение |
|---|---|---|
| npm start | не загружает файл автоматически | Обычный запуск |
| npm run start_verbose | verbose.env | Запуск с DEBUG_LEVEL=verbose, если файл настроен |
| npm run start_debug | debug.env | Отладочный запуск, если файл настроен |
| npm run start_debug_whitelist | debugWhitelist.env | Отладочный запуск whitelist-конфигурации |

Файлы verbose.env и debug.env отсутствуют в текущем репозитории. Скрипт start_debug_whitelist использует отслеживаемый файл с секретами; не используйте его до ротации ключей и исправления хранения конфигурации.

## Логи

Целевой модуль централизованного логирования — `utils/logger.js`.

При его инициализации создаются директории:
- `logs/`;
- `logs/html/`.

Основной JSON log: `logs/app.log`. Payload размером более 500 символов сохраняется через `utils/logFileWriter.js` в отдельные файлы каталога `logs/html/`.

Каталог `logs` исключён из Git через .gitignore.

Часть компонентов также использует `utils/debugHandler.js`, который пишет в консоль и не использует файловую схему целевого логгера. Полная унификация логирования пока не выполнена.

## Тестирование

В package.json нет test-скрипта, а в дереве проекта не обнаружены автоматизированные тесты. Поэтому документированного штатного набора unit/integration тестов сейчас нет.

Ручная проверка API может выполняться через curl или тестовую страницу, но не отправляйте произвольные внутренние или чувствительные URL: текущий endpoint не имеет достаточной защиты от SSRF.

## Диагностика

При проблемах последовательно проверьте:

1. Совпадает ли установленная версия Node.js с 22.22.2.
2. Установились ли прямые зависимости из package.json.
3. Задан ли PORT и свободен ли порт.
4. Присутствуют ли нужные API-ключи в окружении.
5. Какое значение DEBUG_LEVEL используется. Значение verbose меняет не только подробность логов, но и режим получения HTML.
6. Появляются ли записи в logs/app.log и файлы в logs/html.
7. Не пропускает ли домен whitelist или blockedDomains.
8. Не возвращает ли специализированный handler null при отсутствии ключа или ошибке API.

Не включайте подробный лог payload в production без оценки объёма и чувствительности сохраняемых HTML-страниц.
