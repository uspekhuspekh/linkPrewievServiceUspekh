# linkPrewievService

Node.js-сервис для получения предпросмотра веб-ссылок. По URL сервис загружает страницу, извлекает метаданные и возвращает JSON с заголовком, описанием и изображением. Для YouTube и Кинопоиска предусмотрены отдельные обработчики через внешние API.

## Возможности

- HTTP API для получения предпросмотра ссылки.
- Извлечение title, description и image из HTML.
- Потоковая загрузка HTML с ранней остановкой и декодированием разных кодировок.
- Доменные правила в `parsingRules.json` и список блокируемых доменов в `blockedDomains.json`.
- Настройка выдачи постеров и режим `onlyPoster`.
- Специализированная обработка YouTube и Кинопоиска.
- In-memory кеш и single-flight для повторных и параллельных запросов.
- Тестовая веб-страница и клиентский модуль интеграции с CyTube.

## Требования

- Node.js **22.22.2** (версия указана в `package.json`).
- npm.
- API-ключи для интеграций YouTube и Kinopoisk, если эти обработчики нужны.

## Установка и запуск

```bash
npm install
npm start
```

По умолчанию сервер запускается на порту `3002`. Порт можно изменить переменной окружения `PORT`.

После запуска:

- Тестовая страница: http://localhost:3002/
- API: http://localhost:3002/api/parse?url=https%3A%2F%2Fexample.com

Пример запроса:

```bash
curl --get "http://localhost:3002/api/parse" \
  --data-urlencode "url=https://example.com"
```

## API

Основной endpoint:

`GET /api/parse?url=<URL>`

Обычный ответ содержит:

```json
{
  "url": "https://example.com",
  "title": "Example Domain",
  "description": "Example description",
  "image": "https://example.com/preview.png"
}
```

Фактические поля зависят от сайта и выбранного обработчика. При повторном запросе middleware кеширования может добавить `_fromCache: true`; при совместном ожидании одного выполняющегося запроса — `_shared: true`.

## Конфигурация

Основные переменные окружения:

| Переменная | Назначение |
|---|---|
| `PORT` | Порт HTTP-сервера; по умолчанию `3002` |
| `WHITELISTMODE` | Ограничение обработки доменами из `parsingRules.json` |
| `BLACKLISTMODE` | Сейчас читается приложением, но фактически не управляет применением blocklist |
| `IS_POSTERS_ON_BY_DEFAULT` | Разрешение постеров для доменов без отдельного правила |
| `DEBUG_LEVEL` | Уровень подробности отладки; `verbose` также включает полный режим загрузки HTML |
| `LOG_LEVEL`, `LOGLEVEL` | Уровень целевого логгера `utils/logger.js` |
| `YOUTUBE_API_KEY` | Ключ YouTube Data API |
| `KINOPOISK_API_KEY` | Ключ Kinopoisk API |

Не помещайте реальные API-ключи в отслеживаемые Git-файлы. Перед использованием проверьте локальную конфигурацию и используйте секреты окружения или неотслеживаемый локальный env-файл.

В `package.json` также есть команды `start_verbose`, `start_debug` и `start_debug_whitelist`. Первые две ссылаются на `verbose.env` и `debug.env`, которых нет в репозитории. Команда `start_debug_whitelist` использует `debugWhitelist.env`; не запускайте её до проверки и замены секретов в этом файле.

## Структура проекта

- `app.js` — запуск Express и подключение маршрутов.
- `routes/` — web- и API-маршруты.
- `middleware/singleFlightCache.js` — кеширование и объединение параллельных запросов.
- `previewGeneratorEngine/` — основной конвейер получения HTML, извлечения метаданных и выбора изображения.
- `utils/` — вспомогательные функции, специализированные обработчики и логирование.
- `parsingRules.json`, `blockedDomains.json` — доменные настройки.
- `public/`, `views/` — клиентские ресурсы и тестовая страница.

## Известные ограничения

Документация и статический аудит описывают текущее состояние кода, а не исправленную версию. В частности, перед публичной эксплуатацией необходимо отдельно решить вопросы SSRF-защиты входящих URL, хранения API-ключей и безопасного вывода недоверенных метаданных в тестовой странице. См. [результаты аудита](docs/audit.md).

Автоматизированный набор тестов и test-скрипт в текущем проекте не обнаружены. Кеш хранится в памяти процесса и очищается при перезапуске.

## Логирование

`utils/logger.js` — целевой централизованный логгер проекта: он пишет консольные и JSON-логи, а крупные payload сохраняет через `utils/logFileWriter.js`. Часть кода пока использует отдельный `utils/debugHandler.js`; переход на единый логгер запланирован как отдельная задача и ещё не выполнен.
